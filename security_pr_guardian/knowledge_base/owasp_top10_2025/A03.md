# A03:2021 — Injection

## Descripción

Inyección ocurre cuando datos no confiables se envían a un intérprete como parte de un comando o query. Los tipos más comunes incluyen SQL, NoSQL, OS command, LDAP, XPath, y expression language injection. XSS también se considera un subtipo de injection (en el navegador).

## CWEs relacionados

- CWE-89 (SQL Injection)
- CWE-78 (OS Command Injection)
- CWE-79 (Cross-site Scripting / XSS)
- CWE-94 (Code Injection)
- CWE-917 (Expression Language Injection)

## Indicadores en code review

- String concatenation/formatting cerca de llamadas a base de datos
- `shell=True` en subprocess con variables externas
- `os.system()` con input del usuario
- Template rendering sin autoescape habilitado
- `eval()`, `exec()` con datos no confiables
- Queries ORM usando `.raw()` o `.extra()` con input sin sanitizar
- LDAP queries construidas por concatenación

## Mitigaciones

- Usar APIs parametrizadas/prepared statements (la defensa #1)
- Validar input del lado del servidor con whitelist
- Escapar caracteres especiales según el contexto del intérprete
- Usar LIMIT y otros controles SQL para prevenir disclosure masiva
- Activar autoescape en engines de templates
- Nunca usar `eval()` o `exec()` con input externo

## Severidad típica

CRITICAL — injection frecuentemente permite RCE, acceso completo a datos, o toma total del sistema.
