# A04:2021 — Insecure Design

## Descripción

Diseño inseguro es una categoría amplia que representa debilidades fundamentales en el diseño de la aplicación. Se diferencia de implementación insegura: un diseño perfecto puede tener defectos de implementación, pero un diseño defectuoso no se arregla con una implementación perfecta.

## CWEs relacionados

- CWE-209 (Generation of Error Message Containing Sensitive Information)
- CWE-256 (Plaintext Storage of a Password)
- CWE-501 (Trust Boundary Violation)
- CWE-522 (Insufficiently Protected Credentials)

## Indicadores en code review

- Ausencia de rate limiting en funcionalidades críticas
- Falta de validación de lógica de negocio (ej: precios negativos, cantidades imposibles)
- Trust boundaries no definidas (confiar en datos del cliente sin validar)
- Ausencia de mecanismos anti-automatización (CAPTCHA, throttling)
- Flujos de recuperación de contraseña que revelan existencia de cuentas

## Mitigaciones

- Establecer y usar un ciclo de desarrollo seguro (Secure SDLC)
- Usar threat modeling para flujos críticos
- Integrar lenguaje de seguridad y controles en user stories
- Implementar validación de lógica de negocio (no solo validación de formato)
- Separar capas del sistema con trust boundaries claras
- Limitar consumo de recursos por usuario/sesión

## Severidad típica

MEDIUM a HIGH — el impacto depende del contexto de negocio.
