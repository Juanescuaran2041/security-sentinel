# A10:2021 — Server-Side Request Forgery (SSRF)

## Descripción

SSRF ocurre cuando una aplicación web obtiene un recurso remoto sin validar la URL proporcionada por el usuario. Permite al atacante forzar a la aplicación a enviar requests a destinos no previstos, incluso cuando está protegida por un firewall, VPN, u otra lista de control de acceso de red.

## CWEs relacionados

- CWE-918 (Server-Side Request Forgery)

## Indicadores en code review

- Funciones que aceptan URLs del usuario y hacen requests (download, preview, webhook)
- Acceso a metadatos de cloud: `http://169.254.169.254/` (AWS, GCP, Azure)
- Redirecciones no validadas que pueden apuntar a recursos internos
- Parseo de URLs que permite esquemas como `file://`, `gopher://`
- Webhooks configurables por el usuario sin validación de destino

## Mitigaciones

- Sanitizar y validar todas las URLs proporcionadas por el usuario
- Implementar allowlist de dominios/IPs permitidos
- No enviar respuestas raw al cliente (evita exfiltración de datos internos)
- Deshabilitar redirecciones HTTP automáticas
- Bloquear acceso a rangos de IP internos (RFC 1918) y a link-local (169.254.x.x)
- Usar DNS resolution y verificar que la IP resuelta no es interna antes de conectar

## Severidad típica

HIGH a CRITICAL — en ambientes cloud, SSRF puede comprometer el metadato service y obtener credenciales IAM temporales.
